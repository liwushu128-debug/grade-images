# Security policy

## Supported version

Security fixes are applied to the latest revision on the default branch until tagged releases are introduced.

## Reporting a vulnerability

Use GitHub's private vulnerability reporting feature from the repository's **Security** tab. Include the affected command, input characteristics, expected behavior, observed behavior, and a minimal reproduction when it is safe to share.

Do not publish exploit details, malicious image files, or sensitive photographs in a public issue. If private reporting is unavailable, open a public issue containing only a request for a private contact channel.

Relevant reports include crafted image or profile files that cause unsafe file access, unexpected code execution, input overwrite, path traversal, denial of service, or bypass of the strict recipe whitelist.
